Capítulo 01
Introducción y Visión General

Linux AI Ops Studio es una plataforma full-stack de administración autónoma de servidores Linux. Combina telemetría en tiempo real, gestión de procesos y servicios, terminal SSH, explorador SFTP, auditoría de seguridad CIS y un sistema multiagente de IA — todo en una interfaz web unificada.

✅
Propósito central

Reducir el tiempo de respuesta ante incidentes Linux desde minutos a segundos. El agente IA genera planes de acción auditables con control granular de riesgo (bajo / medio / alto) antes de ejecutar cualquier comando.

Arquitectura del Sistema

Principios de Diseño

🏗️

Monolito intencional

Todo el backend vive en server.ts. Sin microservicios. Despliegue de 1 proceso.

⚡

Polling + Cache

El frontend sondea estado cada 6s. El servidor cachea las respuestas SSH 30s para no saturar las conexiones.

🔒

Credenciales cifradas

Las contraseñas y claves privadas se almacenan en SQLite con cifrado AES-256-CBC antes de escribirlas a disco.

🤖

IA con control de riesgo

Cada comando generado por IA recibe un nivel low/medium/high antes de ejecutarse. El usuario aprueba o rechaza.

🖥️

Dual mode SSH

Modo simulado para demos (IPs mock), modo real para producción. Sin diferencia de interfaz para el usuario.

📱

Responsive

3 columnas en desktop (xl:), vista de panel único con tabs en mobile. Sin frameworks de UI externos.

Capítulo 02
Vault de Credenciales SSH

El SSH Connection Vault es el punto de entrada de la plataforma. Administra un pool de servidores Linux con sus credenciales de acceso, persistidas cifradas en SQLite y con un asistente de 6 pasos para incorporar nuevos nodos de forma segura.

Fig. 2.1 — Vista general de la aplicación. El Vault ocupa la columna izquierda (1/5 del ancho).

Asistente de Conexión (6 pasos)

  • 1

    Identidad del servidor

    Nombre descriptivo, dirección IP/hostname y puerto SSH (por defecto 22).

  • 2

    Credenciales de usuario

    Nombre de usuario Linux. Soporte para usuarios no-root con escalación posterior vía sudo o su.

  • 3

    Método de autenticación

    Selección entre contraseña o clave privada PEM. La clave se analiza automáticamente (RSA, ECDSA, ED25519, DSA, OpenSSH, PKCS8).

  • 4

    Verificación de huella

    El cliente calcula y muestra el fingerprint SHA-256 y MD5 de la clave privada para auditoría.

  • 5

    Test de conectividad

    Llamada POST /api/servers/test-connection que verifica acceso SSH real antes de guardar.

  • 6

    Guardar en Vault

    Las credenciales se cifran AES-256-CBC y persisten en .linux_ai_ops.sqlite3. El servidor queda disponible para todas las sesiones futuras.

Gestión de servidores

AcciónDescripción
ConectarEstablece sesión SSH y comienza polling de estado cada 6s
DesconectarMarca servidor como offline, limpia caché de estado
SeleccionarActiva el servidor en Dashboard e Intelligence Center
EliminarBorra del Vault y de la base de datos SQLite
Limpiar unusedElimina masivamente servidores sin actividad reciente

⚠️
Seguridad de credenciales

Las contraseñas y claves privadas nunca viajan en texto plano al cliente. En el Vault solo se almacena el nombre, host, puerto y tipo de auth. Las credenciales salen del servidor únicamente para establecer la conexión SSH.

Capítulo 03
Dashboard de Monitoreo

El Dashboard centraliza toda la telemetría del servidor activo: métricas de hardware en tiempo real, procesos, servicios systemd y contenedores Docker. Los datos se sincronizan cada 6 segundos vía GET /api/servers/:id/state.

Panel de métricas principales

Gráficos de actividad en tiempo real

Live CPU Activity

Historial de hasta 20 muestras visualizado como wave bar chart. Colores adaptativos: verde (<60%), ámbar (60-85%), rojo (>85%). Los datos se mantienen solo en memoria del navegador — se resetean al recargar.

Memory Resource Commit

Barra de progreso commit charge con valores absolutos en GB. Muestra used vs free available en tiempo real. Alimentado por /proc/meminfo vía SSH.

4.2 SFTP Browser

Fig. 4.1 — SFTP Browser. Explorador de directorios con upload drag-and-drop y editor inline.

El SFTP Browser navega el sistema de archivos del servidor remoto mediante la API /api/servers/:id/sftp/*. Características principales:

Navegación de directorios

Listado con tipo (archivo/directorio), tamaño, permisos y fecha de modificación. Breadcrumb clickeable.

Upload con cola

Hasta 3 uploads concurrentes. Barra de progreso individual, velocidad en bytes/s, cancelable con XHR abort.

Download inteligente

Archivos <500 MB: descarga buffereada. Archivos ≥500 MB: redirección al endpoint nativo del browser.

Editor inline

Abre archivos de texto directamente en el browser. Edita y guarda con PUT /api/servers/:id/sftp/put.

Explicación IA

Botón "Explicar con IA" envía el contenido del archivo a OpenRouter para obtener descripción en español.

Límites de seguridad

El editor carga máx. 100 KB. Archivos binarios o de gran tamaño se descargan directamente.

Capítulo 05
Multiagente Copilot IA

El Multiagente Copilot es el componente estrella de la plataforma. Integra OpenRouter para convertir instrucciones en lenguaje natural en planes de ejecución auditables. Cada plan se presenta paso a paso con nivel de riesgo y requiere aprobación explícita del operador antes de ejecutar comandos sensibles.

Agentes disponibles

🖥️

SysAdmin

Disco, CPU, procesos núcleo, systemd.

🛡️

Security

Vulnerabilidades, SSH, UFW, fail2ban.

⚙️

DevOps

CI/CD, Ansible, git, despliegues.

🐳

Docker

Containers, Compose, Portainer.

📊

Monitoring

Logs, alertas, diagnóstico RAM/CPU.

Modos de control de autonomía

ModoComportamiento
Sugerencia Solo genera el plan. Nunca ejecuta comandos sin que el usuario cambie de modo. Ideal para explorar opciones.
Semi-Autónomo Ejecuta automáticamente pasos de riesgo low. Los de riesgo medium y high requieren aprobación individual.
Totalmente Autónomo Ejecuta todos los pasos del plan sin interrupciones. Requiere confianza máxima en el agente.
Flujo de aprobación de comandos

Contrato JSON de respuesta IA

El endpoint POST /api/openrouter/run-agent espera que el modelo devuelva exactamente este formato. El parser tryParseJson() tolera respuestas envueltas en markdown (```json … ```):

      "title":       "Uso de disco por partición",
      "description": "Lista el espacio libre y usado en todas las particiones.",

    },
    {
      "id":          "step-2",

💡
Fallback sin API key

Si OPENROUTER_API_KEY no está configurada, el servidor usa generateSimulatedAgentAction() que devuelve un plan cableado según el rol activo. La interfaz funciona completamente en modo demostración.

Capítulo 06
API REST

Todos los endpoints sirven y consumen JSON. El servidor corre en http://localhost:3005 por defecto. No hay autenticación — diseñado para uso en red local o detrás de un proxy inverso con auth.

Servidores y conexiones

GET/api/serversLista todos los servidores del vault
POST/api/serversRegistra un nuevo servidor (name, host, port, username, authType, password?, privateKey?)
DELETE/api/servers/:idElimina servidor del vault y de SQLite
POST/api/servers/:id/connectMarca servidor como conectando e inicia SSH
POST/api/servers/:id/disconnectDesconecta y limpia caché de estado
POST/api/servers/test-connectionVerifica credenciales SSH sin guardar
POST/api/servers/cleanup-unusedElimina masivamente servidores sin actividad

Estado y telemetría

GET/api/servers/:id/stateEstado completo: server, processes, services, docker, logs, cronJobs, securityAssets (cacheado 30s)
POST/api/servers/:id/executeEjecuta comando SSH → { stdout, stderr, exitCode, riskLevel }
GET/api/servers/:id/sftp/lsLista directorio SFTP (?path=…) → { entries[] }
GET/api/servers/:id/sftp/getDescarga archivo (?path=…) → stream binario
POST/api/servers/:id/sftp/putSube o actualiza archivo (multipart/form-data)

Seguridad y AI

POST/api/servers/:id/hardening-scanEjecuta script CIS bash → { policies[], summary }
POST/api/openrouter/run-agentGenera plan de acción IA → { explanation, riskLevel, steps[], reportSummary }
GET/api/openrouter/statusVerifica conexión a OpenRouter → { connected, model }

⚠️
Nota de producción

El estado en memoria (db) se resetea al reiniciar el servidor, excepto las conexiones que se recargan desde SQLite. Para persistencia completa de logs, procesos, etc., se requeriría una base de datos externa.

Modos de ejecución SSH

🎭
Modo simulado

Se activa automáticamente cuando el host es 192.168.1.10 o 192.168.1.12 (IPs mock) o cuando no hay credenciales. runSimulatedCommand() devuelve respuestas cableadas para los comandos más comunes de Linux.

🔌
Modo SSH real

Para cualquier otro host con credenciales válidas. Usa la librería ssh2 para ejecutar comandos reales. Compatible con CentOS 7, Ubuntu 20/22, Debian 11/12, RHEL 8/9.

Capítulo 08
Auditoría de Seguridad — CIS Hardening

El módulo de hardening ejecuta 22 comprobaciones en una sola llamada SSH. El script bash recoge los valores en crudo y el servidor los normaliza a objetos HardeningPolicy con PASS/FAIL/WARN, risk_score (0-100) y comandos de remediación listos para copiar y ejecutar.

Categorías de control — distribución de checks

Niveles de severidad

Cada control tiene un risk_score de 0 a 100. Los controles con FAIL suman al puntaje total de riesgo del servidor.

Severidadrisk_score FAILCategoría
HIGH70–95 puntosSSH, Firewall, ASLR, Cuentas
MEDIUM40–65 puntosTimeouts, Permisos, Kernel params
LOW10–30 puntosX11, Configuraciones menores

Remediación asistida

Para cada control con FAIL, el sistema proporciona el comando exacto de corrección:

# SSH-001: Deshabilitar root login
sed -i 's/^PermitRootLogin.*/PermitRootLogin no/' \
  /etc/ssh/sshd_config
systemctl restart sshd

# SSH-002: Deshabilitar auth por contraseña
sed -i 's/^PasswordAuthentication.*/PasswordAuthentication no/' \
  /etc/ssh/sshd_config
systemctl restart sshd

Tras ejecutar el scan, el botón "Analizar con IA" envía todos los resultados a OpenRouter para obtener un resumen ejecutivo con prioridades de remediación en español.
